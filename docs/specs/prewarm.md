# 后台扫描（原空闲预跑）

- 来源 task：t031、t043、t057、t048
- 生效范围：应用运行期间的后台只读扫描、结果持久化与定期刷新
- 最后更新：2026-10-18

## 行为契约

- 五个只读扫描项——卸载名单、安装包名单、`clean --dry-run`、`optimize --dry-run`、`purge --dry-run`——各自使用独立命令通道，可同时运行；任意项不因其他项耗时而排队等待。
- 扫描服务（`BackgroundScanService`）是全部名单扫描的唯一所有者，持有运行中任务、请求身份、版本、最后成功快照与当前进度；页面移除独立名单扫描通道，统一经 `request`/订阅消费进度与结果。
- 任务执行纳管于应用全局 `HeavyScanScheduler`：在实际运行前取得调度名额（生产默认名额 3），释放名额涵盖子进程和内部 worker 完整生命周期；当前可见页面请求提升为 userVisible 优先，后台同批启动按固定次序（卸载、安装包、clean、optimize、purge）入队并具有防饥饿保证。
- 持久化串行存储所有者（`BackgroundScanStorage`）：文件 I/O、JSON 编解码及 clean-list.txt 读取解析均离开 MainActor；MainActor 仅提交不可变快照并消费状态。
- 服务拥有显式 hydration 状态：启动时异步由存储所有者加载缓存；迟到加载按输入版本/修订号合并，不得覆盖内存中已接受的新扫描结果，未完成加载前不发布成功空缓存造成页面闪空。
- 普通成功结果采用可注入时钟的 100 ms 尾沿合并（持续多次更新时每 500 ms 至少推进一次落盘水位，防止写延迟无限拖延）；失效版本与用户明确移除作为优先操作立即串行写入，不受合并窗口延迟限制。显式 flush/close 可等待持久化水位并完成尾批落盘。
- 渐进进度与完整快照分离：流式输出过程发布进度（最长 100 ms 聚合发布），成功完成时更新快照并提交存储落盘；失败或取消不污染已有的成功快照，页面离开仅取消订阅，不终止共享底层任务。
- 启动时完成 hydration 后，缺失或超过 24 小时的项自动重扫。应用运行期间每 24 小时按需重扫，结果未到期不重复扫描（手动刷新与写入失效除外）。
- 每项结果带 `capturedAt` 持久化到 `~/Library/Application Support/zmole/background_scan_cache.json`（Schema 2）；原子写失败保留上次完整文件与待写快照，错误状态可观察且可重试，不阻塞已核验的业务操作。缓存文件损坏或 schema 版本不匹配时整文件忽略并按无缓存安全恢复，不抛异常到页面。
- 唯一互斥是 clean：用户 clean 执行开始前，后台 clean 扫描被取消，且必须等待其底层进程完全退出及后台 clean-list.txt 读取解析任务完全退出释放文件所有权；写入租约持有期间 clean 不启动，租约释放后自动补跑。`clean-list.txt` 不会出现两个并发写入者。
- 同一项已有扫描运行时，刷新请求复用该次运行，不产生第二个同类进程；完成后结果与 `capturedAt` 更新。
- 写入成功（协调器失效信号）使全部后台结果失效并触发重扫；确认框打开期间新结果不替换正在确认的数据。
- 单项失败不阻塞其他项：保留上次成功结果并暴露失败状态；无结果的失败最多每小时重试一次。
- 页面打开时若有对应结果直接显示并标出扫描时间；无结果显示扫描中或暂无数据。
- 后台只运行只读命令与 `--dry-run`，不 spawn 无 `--dry-run` 的 clean/optimize，也不 spawn `purge --yes`。
- 无完全磁盘访问权限时安装包扫描不跑（会遍历 Desktop/Documents/Downloads），授权事件到来后自动补跑；其余项不受影响。
- 应用退出时取消所有后台扫描进程。
- demo 模式使用演示 lanes 跑后台扫描（不启动真实 mole），缓存写演示数据目录。
