# 概览与存储估算（overview）

- 来源 task：t016、t026、t034、t036
- 生效范围：概览页与磁盘五段估算
- 最后更新：2026-10-17

## 行为契约

- 概览复用共享 `StatusViewModel` 采样：健康卡（健康分圆环 + 状态文案 + 三个指标 tile）、状态四宫格（CPU/内存/温度/网络）数值来自真实采样；数据缺失显示占位，不伪造数值或趋势。健康分不可用显示占位而非 0。
- 页头右侧「刷新」触发状态重采样，「清理」入口跳转清理页；快捷卡区块与趋势条已移除。
- 存储卡：已用容量大数字、五段分段条与带数值图例；估算不完整时如实标明。
- 五段估算：`/Applications`、`/System` 顶层子项（排除 `/System/Volumes`）、`~/Library/Developer`、`/Users` 减开发者、其他 = 全盘已用 − 四段之和（负值按 0）。任一输入缺失该段为空占位，不填演示常量。探测经 3 条估算通道并发执行（单通道串行）。
- 触发：进入概览即启动目录扫描，不等 status 采样；status 迟到只更新「其他」段（不重扫）；写入失效信号与缓存过期触发全量重算。估算任务由 ViewModel 持有，离开页面不取消。
- 缓存：`~/Library/Application Support/zmole/storage_estimate.json`（含 schemaVersion/capturedAt）。进入概览先用缓存即时渲染；完成的扫描（含部分段）即展示并落盘；缺失段显示占位、保留「估算不完整」标记，并自动补扫一次（只探测缺失段）。超过 TTL（6 小时）或收到写入失效信号时全量重算；超过最大年龄（7 天）或 schema 不符即作废（schema 1→2 的旧缓存全部丢弃）。写入失效落在扫描在飞期间时，即使该次扫描完整结束也保留失效状态，并自动补排一次全量重扫；补偿扫描期间无新失效才清除标记。
- 被取消的扫描（应用退出）不写缓存；估算通道单条命令超时 600 秒，超时段为占位并在下一次触发重试。
- 概览四张卡片（健康、存储、最近活动、系统状态）统一固定高度。
- 最近操作复用 `history --json`：有记录显示标题与时间，空显示空态；history 失败在概览顶部显示错误 banner 与重试（不再静默）。
- 页面无 eyebrow 小字（标题下直接内容）。
