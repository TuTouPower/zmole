# Task spec

## 背景

卸载与安装包页面在无最终缓存时调用 userDidRescan，取消后台任务后自行另起扫描，页面结果不回填后台缓存。后台卸载又只在整流结束后发布。目标是扫描服务统一持有同类任务，页面只表达需求并订阅，避免双通道双状态。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 扫描服务是名单扫描的唯一所有者，持有任务、请求身份、版本、最后成功快照、当前进度、错误和新鲜度；页面自己的名单扫描通道及接管分支移除，执行/身份核验通道保留。
- 打开与刷新通过同一 request/subscribe 接口进入：兼容版本已排队或执行时复用；有效缓存立即展示；缺失或过期时只请求一次。语义相同的请求共同消费进度，不能把取消订阅等同于取消底层共享任务。
- 上次成功结果与本次部分进度分别保存。卸载合并行在进程完成前发布，刷新合并最长 100 ms，并在行停止到达时按计时器交付尾批。部分结果不更新最后成功时间、不落为完整缓存，名单未成功完成时禁止卸载。
- 共享任务成功后统一提交完整快照到后台缓存，capturedAt 来自完成时刻。失败或取消保留上次成功快照及错误/取消状态，不把部分结果认证为完整。
- 页面离开只解除页面订阅，后台新鲜度需求仍可保持任务；显式取消刷新由服务处理并向所有订阅者发布一致终态。写入接管和失效使用 t047 的版本规则，迟到旧版本事件不能覆盖新快照。
- 确认绑定稳定名单版本；扫描完成或进度发布不能偷偷替换正在确认的身份集合。

### 非范围

- 重写卸载身份核验、安装包删除语义或名单 JSON 字段。
- 元数据 worker 生命周期与资源名额，分别由 t053、t048 提供。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

- [ ] AC-001：后台卸载名单扫描未完成时打开页面，不取消、不启动第二个流，页面最终采用该次成功名单。
- [ ] AC-002：流已产生行但尚未结束时页面能看到合并行；最后一行到达后即使无后续行，100 ms 内也能发布尾批。
- [ ] AC-003：后台安装包扫描未完成时打开页面，不取消、不重复启动，完成后显示同一份名单。
- [ ] AC-004：刷新复用同版本正在排队或执行的任务；无任务时只启动一次。并发打开、刷新与周期检查也只启动一次。
- [ ] AC-005：有效缓存直接展示；缺缓存只启动一次；过期缓存先带过期标记展示，再请求一次刷新。
- [ ] AC-006：共享扫描成功后缓存含完整结果和完成时间；24 小时内周期检查不重扫，过期后仍正常触发。
- [ ] AC-007：扫描先发布部分行后失败或取消，最后成功快照及 capturedAt 不变；部分行不被存为成功缓存，也不能用于卸载执行。
- [ ] AC-008：两个订阅者中一个离开不终止另一方正在使用的任务；显式取消由服务统一终结并通知全部订阅者，不遗留假忙碌状态。
- [ ] AC-009：写入导致版本变化后，迟到的旧进度和成功结果不覆盖新版本；确认期间绑定名单保持不变。

### 风险与回退

- 风险：一份 results 同时承担完整缓存和部分进度会把半张名单存成成功；两者状态分开。
- 回退：撤回共享名单服务改动并丢弃新生成的派生缓存；不能同时保留新旧两个名单所有者。

### 依赖与约束

- 依赖 t047 的结果版本、写入事件与新鲜度。t048 后续只在实际任务入口增加资源准入。
- 与 t055 共改名单模型/页面模型；与其他 App 装配和页面修改通过 conflicts_with 串行化。
