# Task spec

## 背景

概览「存储估算」五段常只显示「应用程序」一个值，其余为「—」，环形图退化为灰色占位。实测持久缓存只含 `applications`。根因分析与证据见 p012：一是 t026 的 `computeEstimate` 在扫描被取消后仍把不完整 `sums` 落盘并由 `primeEstimate` 当权威立即渲染；二是 `mole analyze /System` 递归包含 `/System/Volumes`（整个数据卷 + 快照），实测 128.9s 超过 120s 超时，且口径错误（真实只读系统卷约 12 GiB）。用户 2026-10-17 确认：系统段只计只读系统卷（排除 `/System/Volumes`）。

## 契约区

### 范围

- 扫描被取消或未完成时，不把不完整结果持久化为可用缓存，不据此渲染为权威估算。
- 「系统」段改为只计只读系统卷：`analyze /System` 结果排除 `/System/Volumes` 后的和；该口径下扫描时长降到秒级，不再触及 120s 超时。
- 不完整缓存（含历史遗留的部分缓存）在下次进入概览时触发重算并最终被完整值覆盖。
- 修正后五段（系统/应用程序/用户数据/开发者/其他）在正常环境下均能给出数值或明确的不可用原因。

### 非范围

- 不改五段划分本身与颜色/文案。
- 不引入新缓存机制或后台定时任务。
- 不改 `mole` 二进制。
