# Task spec

## 背景

get_brew_cask_name 的回退按应用重复遍历 Caskroom、执行 brew list/info。对三个应用调用生产回退函数已得到三次 list 和三次 info。一次扫描建立索引可减少重复，但来源检测决定卸载 token，不能以同名唯一替代路径所有权核验。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 在名单扫描父级建立只读扫描索引：installed token 快照和每个存在 Caskroom 的路径/链接身份至多各读取一次。子 shell 和 worker 接收同一个索引，不在每个命令替换中惰性重建。
- Homebrew 可用且有待解析应用时，父级取得一次已安装 token 快照。已解析进 Caskroom 的真实路径保留路径快判，命中后只核对这份快照，不再遍历 Caskroom；有路径未命中时再按需遍历每个根一次。
- “唯一对应”指真实路径或 device+inode 明确绑定到目标应用且 token 在已安装集合中，不能指 app 名称相同或目录仅有一个候选。
- 名称命中仅形成候选；缺少所有权证据、多个 token、悬空链接或身份变化时做定向核验。仍不能确认则不返回 cask token，不取第一个。
- probe 失败、超时和信号与确定“未安装”分开传递；不能把损坏索引默认为确定来源。卸载执行仍保留当前身份与已安装状态核对，不跨扫描复用旧索引。
- Homebrew 不可用时无 brew 调用，普通应用名单仍可完成。

### 非范围

- 改变卸载命令、--zap 语义和对外名单字段。
- 元数据 worker 生命周期；仅复用当次扫描内索引，不新增跨启动 cask 缓存。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：3 个快路径未命中的应用由真实名单扫描入口解析时，brew list --cask 最多一次，每个 Caskroom 最多遍历一次，跨子 shell 不重建。
- [ ] AC-002：索引有唯一真实路径/文件身份所有权且已安装的应用取得对应 token，不再调用该应用的 brew info。
- [ ] AC-003：多个 cask 含同名应用时，仅候选项可定向核验；其余应用不重复全量查询，未经核验不返回任一 token。
- [ ] AC-005：brew 不可用时不调用 list/info，名单仍完成且这些应用不标 Homebrew。
- [ ] AC-006：仅有唯一同名但目标不是同一应用、悬空链接、未安装 token 或扫描中路径身份变化时，不把该目标认作该 cask。
- [ ] AC-007：索引读取或定向 probe 超时/失败不被认定为确定未安装；失败状态可观察且不导致错误卸载名。
- [ ] AC-008：两次名单扫描各自读取当时索引，第二次能发现 token 或链接变化；卸载执行的身份与 installed 核对仍有效。
- [ ] AC-009：全部应用均走路径快判时，整轮只执行一次 list、Caskroom 遍历为 0；残留目录对应 token 已不在安装快照时，不返回该 cask。

### 风险与回退

- 风险：命中同名就返回 token 会把应用指向错误卸载对象，所有权必须有路径或身份依据。
- 风险：Bash 子 shell 的内存变量不回传，父级扫描索引须显式传递。
- 回退：撤回扫描索引路径与相关临时文件，保留原所有权验证，不保留双实现长期分支。
