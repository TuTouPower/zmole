# Task spec

## 背景

UninstallView.visibleListings 在 body 求值时过滤排序；sizeBytes 反复调用 HumanSizeParser，图标发布又触发重排。500 条 Release 夹具复核约 69 ms，解析一次再排序约 1.9 ms，只证明局部热点。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 名单解码/合并时归一化整数大小并作为唯一排序输入；原始文本只用于协议与必要展示，整数和文本不能独立可写。无法解析保持未知，保持现有 HumanSizeParser 语义。
- 名单内容版本与图标状态分离；过滤和排序缓存以内容版本、搜索词、来源筛选、排序条件及参与比较的 Locale 为键。图标不推进内容版本。
- 已排序结果保存稳定行身份，行图标从独立状态读取，避免缓存整份行快照冻结图标。
- 保持现有次序：名称 localizedStandardCompare 升序；大小已知降序、未知最后，同大小名称降序；来源空字符串在前、来源升序，同来源名称升序。完全相同键保持稳定身份顺序。
- 选择合计使用同一归一化大小，未知不计入并保留未知提示。

### 非范围

- 名单扫描所有权、确认身份与对外 JSON 字段。
- 改变 HumanSizeParser 对裸 0 等原有输入的处理。

## 上下文区

### 有意不测

- 不承诺产品打开时间或固定提速倍数；不因 CI 耗时噪声判失败。

### 测试策略

- 混合已知、未知、同大小、同名、空来源和非空来源；独立列出预期身份顺序，不照抄被测比较器生成答案。
- 计数解码/合并与比较阶段解析；更新图标后验证显示更新、排序次数不增。
- 分别改变每个缓存输入并验证失效；注入 Locale/比较环境，验证切语言不会沿用旧键。
- 保留原有解析器语义测试，数值模型不能把未知改成 0。

### 风险与回退

- 风险：同时保存可变文本与可变数值会形成双真相，统一在归一化入口更新。
- 风险：缓存行副本会让图标不更新，缓存稳定身份与排序映射。
- 回退：撤回模型和派生缓存；名单协议及已缓存原始数据不变。
