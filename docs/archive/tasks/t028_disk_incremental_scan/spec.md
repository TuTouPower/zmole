# Task spec

## 背景

磁盘页每次进入目录都新起一次 `analyze-go --json <path>`。该进程走完整棵子树后只返回直接子项，子树随进程退出丢弃。父目录扫完再进入子目录仍会重走同一批文件；返回后再进入同样从头算。扫描期间当前名单被清空，整页变成等待，且导航被加载状态锁住。单次超时后大目录直接失败。

同时页面的浏览交互与 WizTree 式体验差距明显：进入目录只能靠列表行右侧的独立按钮；容量方块点击只更新选中高亮，不能下钻；左右两栏宽度固定（`AnalyzeView.swift` 约 line 52 `directoryPane.frame(minWidth: 340)`）；列表只有文件名与大小两列，无法直观看出各项占父目录的比例。

用户已确认（2026-10-17）：磁盘页改为应用内只读扫描。点进目录先列出直接子项，目录大小随后补上；同一次会话里已扫完的层级再进入不再重走文件。同日提出交互改造，并给出 WizTree 截图作为百分比列与柱形条参考。

## 契约区

### 范围

- 磁盘页打开后浏览扫描根的直接子项。生产扫描根是 `/`。测试与 demo 使用注入的扫描根，不读注入根以外的路径，不 spawn mole。
- 进入目录后，先列出直接子项名称。直接文件的大小与名单同时出现。子目录大小在后台逐个补上。
- 大小尚不知道的子目录标为计算中，不显示为 0 字节，不计入当前层合计，不参与面积图。大小已知后计入合计与面积图。
- 当前层合计等于已计入条目的字节和。面积占比等于该项字节除以该合计。
- 会话内保留每个已扫描目录的直接子项与当时的大小。父目录扫描完成时，其子目录的直接子项一并保留。此后进入该子目录立即展示这份结果。进程退出后不保留。
- 未重新分析前，磁盘上的后续改动不改变已展示的大小。重新分析只重扫当前目录及其子树，并替换这份结果。
- 扫描进行中可以返回上级或改入另一个目录。目标若已有名单，立即显示该名单。页面不被替换成看不到名单的全页等待。
- 某个同级目录仍在计算时，打开另一个尚未开始的目录，后者的直接子项名称先出现。
- 大小尚不知道的目录排在已有大小的条目之后。大小已知后按当前排序归位。搜索只过滤当前层名称，不改变各项字节。
- 单文件展示大小等于 `st_blocks × 512`。同一扫描内，指向同一文件的多个硬链接只计入一次。符号链接只计入链接自身，不计入目标内容。
- 子目录所在设备与父目录不同时，该子目录不计入父目录合计；进入该子目录后单独计算它自己的大小。
- 无法读取的目录标为未扫描，不显示为 0 字节，不计入合计。
- 列表与面积图的选中保持同步。目录可进入，文件可在 Finder 中显示。磁盘页没有删除或移入废纸篓控件。
- 左右两栏分隔可拖动，用户可调整列表与方块图宽度比例。
- 删除列表行靠右的「进入目录」独立按钮。
- 目录进入统一为双击：列表行双击、容量方块双击都下钻进入该目录。
- 列表把文件大小显示在文件名右侧，并新增一列「占父目录大小百分比」。
- 百分比按 WizTree `% of Parent` 口径（占其父目录总量），单元格内附按比例的水平柱形条。

### 非范围

- 不把扫描树写入磁盘，不读不写 `~/.cache/mole/`。
- 不改概览五段估算的目录口径、公式、缓存与 `analyze` 调用。
- 不复现 mole overview 的精选目录、折叠目录名单或 Spotlight 大文件列表。
- 不在磁盘页提供删除、移入废纸篓或清理。
- 不做跨设备的容量合并。符号链接目标不计入。
- 不改变 Finder 打开入口（`analyze.reveal`）。
- 不改变选中高亮语义（单击仍只选中）。
- 百分比只用于展示，不改变排序或分析逻辑。

## 上下文区

- 来源：用户 2026-10-17 口述并确认方案；p010（2026-10-17 核实：`mapTile` 方块当前仅更新 `selectedPath`；`analyze.open_directory` 按钮存在于行内与 inspector；列表无百分比列）。磁盘页现状见 `src/zmole/Features/Analyze/`。`analyze-go` 在捆绑 tag `V1.55.0`（`69ab325d`）会把子树结果写入 `~/.cache/mole/`，但 JSON 模式仍要等整棵子树结束才返回，界面在此之前清空名单。本 task 不复用该缓存。

### 有意不测

- 真实 `/`、`/Users` 或整盘的耗时：不进自动测试。
- APFS clone 的物理块去重：分配块会按文件重复计入，不另测物理唯一块。
- 真实第二块磁盘的挂载：设备号差异由注入目录源验证。
- 拖动分隔线的真实拖拽轨迹：环境无法注入鼠标手势，测其宽度状态变化即可。

### 测试策略

- 注入可控目录源：目录列举立即返回，指定子目录的大小计算可被阻塞，并可报告设备号与读取失败。
- 用临时目录验证符号链接、硬链接、`st_blocks × 512`，以及扫描完成后改文件再重新分析。
- 断言磁盘页路径上的 mole 命令记录不含 analyze。
- demo 使用同一注入目录源，不 spawn 捆绑 mole。
- 百分比计算与柱形条比例抽成纯函数做单元测试（含边界：父目录为 0、文件大小 0、超过 100% 的容错）。
- 下钻行为断言 pathStack/当前根；视图层以状态断言覆盖双击/分隔绑定。

### 风险与回退

- 风险：新口径使用分配块，并会列出 `/` 下 mole overview 原先不展示的目录，磁盘页数字与旧 analyze、概览五段估算不再相同。
- 风险：会话缓存会在用户改完文件后仍显示旧大小，直到重新分析。
- 风险：「父目录总量」在当前快照数据模型中的取法需实现时确认。
- 回退：磁盘页改回每次 `analyze --json`。概览估算不经过这条扫描路径。撤销本 task 提交即可恢复原列表与固定宽度布局。

### 依赖与约束

- 无前置 task。运行于 macOS。扫描只读。不写 `~/.config/mole/`，不写 `~/.cache/mole/`。
- 与 t035 改同一批页面文件，需串行（t035 已声明 conflicts_with）。
- 平台：macOS SwiftUI；不得引入新第三方依赖。
