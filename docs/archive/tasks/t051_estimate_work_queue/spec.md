# Task spec

## 背景

StorageEstimateLoader 按 index % channels.count 固定切片，每片串行。分到 /Users 同片的系统探测会等它返回，另外通道即使空闲也不能领取；OverviewViewModel 等 loadSums 全部返回才发布。目标是估算工作按空闲通道逐项领取，分段一旦完成立即可见。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 估算服务持有待探测队列和本轮分段聚合状态；空闲通道领取下一项，经 t048 统一准入，不能再固定分片，也不建立第二个全局优先级调度器。
- 初始 /Applications、Developer、/Users 三项按此稳定顺序先于系统子项排队；缺段补扫只加入缺失或 t047 指定过期的输入。三个初始项都已开始或完成后，空位可以处理系统子项，无需等 /Users 完成。
- 本 task 仍以现有 analyze 适配器读取目录，接口以输入身份和异步分段事件表达，不把 analyze argv 或三条通道永久写进上层模型。t058 会将后端替换为统一会话测量。
- 应用、开发者、用户与系统各自成功后立即发布；用户段依赖本轮有效 users 和 developer，其他依赖容量与全部有效分段，缺值时占位，不用 0 代替。
- 系统仍跳过 /System/Volumes，任一必要子项失败则系统段不可用，不能发布部分和为完整；无 FDA 不探测 /Users。
- 中间进度只更新本轮展示，不覆盖上次成功缓存时间；完成时按 t047 的输入版本保存完整或明确缺段的结果。取消不认证部分结果，旧世代事件不覆盖新世代。

### 非范围

- Developer 与 /Users 重叠读取由 t058 消除；本 task 不扩 CLI 排除参数。
- 修改 t047 新鲜度、t048 资源公平性、五段计算公式和 600 秒 analyze 超时。

### 风险与回退

- 风险：接口改成 async 却仍末尾一次返回，首段仍不可见；验证 ViewModel 实际中间状态。
- 回退：撤回逐项领取与中间展示变更，保留 t047/t048 的版本和准入，不恢复无界并发。

### 依赖与约束

- 依赖 t048 的资源准入；本 task 负责估算通道池的逐项领取，t047 版本规则通过依赖链获得。
- 本 task 的命令适配器是现有后端隔离点，t058 替换后不保留旧后端兼容层。
