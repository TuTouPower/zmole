# Task spec

## 背景

当前 OperationCoordinator 的单一 invalidationGeneration 同时驱动确认失效、清空五份后台结果和概览重算。执行前后各发一次失效还会重复取消与重扫。源码同时确认跨功能重叠：clean/purge 共用项目目录，clean/installer 覆盖 Homebrew 与 Mail 缓存，optimize 会删除用户缓存。目标是按数据影响失效并合并刷新，不能按功能名只点一项，也不能忽略已经发生的目录变化。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 分离确认世代、结果新鲜度与调度请求。写入产生带唯一 operation ID、生命周期和影响集合的事件；同一次操作只结算一次数据变化，保留全局单写入租约。
- 影响集合集中定义，不让各页面拼接失效列表。默认采用下表；命令能够提供更精确且经验证的修改路径时，可据路径进一步收窄。无法判定的影响取保守并集，不能把未知当无影响。

|操作或配置|失效的后台结果|失效的概览目录输入|
|---|---|---|
|clean 执行|五项；涉及应用、项目、安装包缓存与维护状态|四个目录输入均标过期|
|卸载执行|uninstallList、clean、optimize；未知的 brew zap 影响保守包含 installerList/purge|应用、用户与开发者；无法判定时四项|
|optimize 执行|optimize、clean|用户与系统；未知维护影响取四项|
|purge 执行|purge、clean|按 purge_paths 所在分段；自定义路径无法分类时四项|
|安装包删除|installerList、clean；普通下载目录的目标可经路径规则证明后仅 installerList|用户目录输入|
|clean 白名单保存|clean|无|
|optimize 白名单保存|optimize|无|
|purge_paths 保存|purge、clean，二者共用项目目录配置|无|

- 缓存结果分别记录目标版本、捕获版本、capturedAt 与新鲜度；旧成功载荷继续显示，标记过期。重扫失败仍保留过期状态和旧时间，不把旧结果重新认证为新鲜。
- 执行开始前在内存登记写入中的影响集合，禁止相关旧扫描被认证为新鲜。成功或可能已部分修改的失败/取消，在进程结束和租约释放后按 operation ID 结算一次版本并合并刷新。确认取消、spawn 前拒绝及已确认无变更不刷新。
- 原子配置保存失败且确认文件未变时不新增数据失效；确认世代仍失效、租约释放。成功保存后结算对应影响。既有过期状态不能因一次失败保存被清除。
- 正在进行的受影响扫描先被标记为旧版本，取消并等待；迟到成功不得清除新版本的过期状态。写入期间不启动受影响重扫，结束后每项至多一次；未受影响项继续运行。
- 概览保留旧分段并显示过期，按受影响输入补算，不扫描仍有效输入；结果版本跨在途写入时不能被认证为新鲜。TTL、最大年龄和权限规则继续适用。概览离页后由模型合并一次请求，返回页面可观察过期/刷新状态。
- 新缓存格式保存目标版本、捕获版本与过期状态。旧 schema 缓存整份丢弃后重建，不维护缺少版本的兼容分支。加载/保存顺序接口由本 task 定义，t057 将同一接口搬离 MainActor。
- 缓存只保存可重建的历史快照，不是执行授权或事务日志。缓存写入失败不阻断已通过租约、确认和目标核验的操作；内存结果仍按版本过期，报告存储失败并尽力删除旧派生缓存。缓存显示 capturedAt，不把历史快照伪装成实时值；不承诺业务写入与缓存之间的崩溃原子性。

### 非范围

- 全局资源调度、页面共享扫描和磁盘测量实现。
- 修改删除语义、依据过期后台结果放宽确认或目标身份核验。

- [ ] AC-007：原子白名单或 purge_paths 保存失败且文件未变时，租约释放、确认世代失效；不新增后台过期项或扫描，已有过期状态保持。
- [ ] AC-008：成功写入仍使已打开确认失效；确认打开期间后台结果不能替换绑定的数据。
- [ ] AC-009：clean 执行先取消并等待后台 clean 完全退出；旧成功载荷保留，执行完成前没有竞争 clean 写者。
- [ ] AC-010：clean/purge 项目缓存重叠、installer/clean Homebrew 缓存重叠及 purge_paths 共用配置均按影响表失效；无关项载荷、时间与运行次数不变。
- [ ] AC-011：一次写入的开始、结束和重复完成事件只让每个受影响项重扫一次；扫描在写入进程退出、租约释放后启动。
- [ ] AC-012：发生部分变更后失败或取消，仍刷新影响集合；确认取消、spawn 前拒绝和已确认无变更不启动重扫。
- [ ] AC-013：失效和重扫失败时旧载荷仍可读且标过期；新版本重扫成功才清除过期并更新 capturedAt。
- [ ] AC-014：写入发生后放行旧版本扫描，旧结果不能清除过期；补扫返回新版本后才成为新鲜。
- [ ] AC-015：写入只使受影响概览输入过期并合并补算；未受影响输入不探测，界面在新结果前标记过期。TTL 到期仍刷新。
- [ ] AC-016：已持久化失效版本后、重扫完成前重启，相关缓存仍过期并补扫；旧 schema 不被当成新鲜结果加载。
- [ ] AC-018：未知修改范围采用保守影响集合；提供已验证路径后才收窄，不能因无路径报告而认定无变更。
- [ ] AC-019：缓存持久化或删除旧缓存失败时，已通过业务安全核验的操作仍可执行；受影响内存载荷保持过期，存储错误可观察，不能因缓存失败把旧结果重新认证为新鲜。

### 测试策略

- BackgroundScanTests 逐行验证影响矩阵，覆盖多项失效和不受影响项保持；另测配置失败、重复终态、进程部分失败与 spawn 前拒绝。
- 用持久化故障和重启夹具验证已保存过期版本、存储失败降级与迟到扫描。确认世代和缓存版本必须分别断言，缓存失败不能冒充业务安全失败。

- 不修改仍成立的确认保护与 clean 等待退出断言。

### 风险与回退

- 风险：矩阵过窄会漏失效，过宽会多扫描。所有收窄需目标路径或命令语义证据，并覆盖重叠反例。
- 风险：崩溃可能发生在业务写入与缓存记录之间。缓存是带时间的历史快照，执行安全依赖重新确认与目标核验，不为派生缓存引入业务事务日志或写入前置门禁。
- 回退：撤回本 task 后丢弃新格式派生缓存，保留用户配置及历史；旧程序按缺缓存重建。
