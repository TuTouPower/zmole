## 已核对的事实

这些不是问题。推荐都建立在这些事实上。

- 现有应用是 SwiftUI 窗口。顶部五个模式：清理、软件、优化、分析、状态。软件里含卸载和保护规则，优化里含项目清理，状态里含历史。执行只走捆绑 mole，tag `V1.55.0`（`69ab325d`）。
- Demo 是另一套结构：侧边栏 10 页（概览、清理、卸载、磁盘、优化、状态、项目清理、安装包、历史、设置），外加 ⌘K、确认框、toast。容量、健康分、进程、72% 扫描进度是写死的。
- `mo clean` 已删除 `--select`、`--categories`、`--exclude`。不能把界面勾选交给 CLI。排除路径只能写 `~/.config/mole/whitelist`。正式执行会重扫，不保证沿用上一次 dry-run 文件。
- 清理走 `safe_remove`，直接 `rm -rf`。`mole_delete` 的废纸篓/永久删除开关不用于清理。没有环境变量能把清理改成移到废纸篓。清理还会永久清空 `~/.Trash`，除非把这个路径写进白名单。
- `MOLE_DELETE_MODE` 只对走 `mole_delete` 的路径有效，默认 `permanent`。卸载脚本自己把默认改成 `trash`。安装包删除也走 `mole_delete`，但脚本没有改这个默认，所以现在是永久删除。
- `mo optimize` 只有 `--dry-run` 和 `--whitelist`。没有按任务挑选的参数。
- `mo purge` 只有 `--dry-run`、`--yes`、`--paths`、`--include-empty`。非交互执行删的是引擎自己认定的项。扫描目录文件是 `~/.config/mole/purge_paths`。
- `mo installer` 会进全屏选择菜单。`--dry-run` 也进这个菜单。没有 JSON，没有按路径删除的参数。扫描目录包括下载、桌面、文稿、Homebrew 缓存等；ZIP 要先看出里面有没有 app/pkg/dmg/xip 才算安装包。删除走 `mole_delete`，默认永久删除。
- `status --watch --interval` 的 JSON 含健康分、CPU、内存、磁盘容量与读写、网络、温度、风扇、电池、进程表、僵尸进程数。不含 demo 那种「系统 / 应用 / 用户数据 / 开发者 / 其他」五分类。
- `analyze` JSON 是当前目录的 `name`、`path`、字节 `size`、`is_dir`。没有更细的文件类型，没有删除接口。
- `uninstall --list` 只有 name、path、bundle id、source、uninstall name、人类可读的 size 字符串。没有版本、最近使用、关联路径。关联路径要等该项自己的 dry-run。
- `history --json` 可以导出。clean 白名单是路径，文件 `~/.config/mole/whitelist`。optimize 白名单是任务 id（例如 `sqlite_vacuum`），文件 `~/.config/mole/whitelist_optimize`。另一批安全默认路径会在清理时强制并入，界面删不掉。
- 优化任务是 `catalog.sh` 里的固定清单，和 demo 里那几条文案不是一一对应。其中 LaunchAgents 清理在发现目标二进制缺失时会删除 plist。
- 仓库里 `t014` 还在 backlog，整理的是旧顶部导航。
- 既有决策见 `docs/blueprint/decisions.md`：SwiftUI + 捆绑 mole、不进 PATH、GitHub zip 不公证、不做 TUI 代按键、GPL、三语、产品名 zmole、卸载身份用 path。

### 清理

❓ **Q12** - **删除落到哪里**

已决（2026-10-16）：**否。** 清理改为移入废纸篓，不做永久删除。卸载维持移到废纸篓。

要实现这一点，必须改捆绑 mole 的 clean 删除实现。现有 `mo clean` 走 `safe_remove` → `rm -rf`，不读 `MOLE_DELETE_MODE`。废纸篓失败时停止并报告，不退回 `rm -rf`。

还没定的是同一次清理要不要继续清空废纸篓，以及项目清理、优化删除是否同样改道。见 Q54、Q55。

❓ **Q13** - **清理不能按勾选执行**

清理页保留 demo 的分类列表、体积和「再次扫描」。不提供「只删除勾中的项」。不想删的路径通过「保护」写入 clean 白名单，然后预览作废并重扫。主按钮是检查完整预览后执行一次完整 clean。安全默认路径即使从编辑器里去掉，下次清理仍会保护。废纸篓是否还出现在这次清理里，由 Q54 决定。

依赖：Q1、Q12。

**推荐：是。**

mole 已去掉按分类选择的参数。把勾选假装成执行范围，会和真实删除不一致。

❓ **Q14** - **扫描进度**

已决（2026-10-16）：**是。** 扫描中显示 mole 实际打印的当前阶段名。已知阶段翻译成界面语言，例如 `Browsers` 显示为「浏览器」；不认识的阶段显示原文。不显示百分比，不用阶段序号冒充百分比，不挂 PTY。阶段切换前保留不确定的活动指示，表示仍在这一阶段里。

❓ **Q15** - **保护范围侧栏**

清理页右侧显示 mole 的保守策略说明、当前 clean 白名单条数，并链到白名单管理。不把 demo 里写死的四个路径当成这次扫描结果。

依赖：Q5、Q13。

**推荐：是。**

### 磁盘

❓ **Q20** - **磁盘浏览**

磁盘页按 demo 做成左列表、右面积图。支持面包屑、返回上级、当前目录搜索、按大小或名称排序、单击同步选择、箭头展开、双击进入目录。类型只有目录和文件。

方块面积只用当前这一层 entries 的字节。选中项在列表和面积图之间同步。小方块仍能从列表选到。没有删除按钮。

依赖：Q20。

**推荐：是。**

❓ **Q22** - **概览磁盘五段用目录估算**

概览磁盘环显示五段，数字来自本机测量，不读取系统设置的私有存储分类。

- 应用程序 = `analyze` 的 `/Applications`
- 系统 = `analyze` 的 `/System`
- 开发者 = `analyze` 的 `~/Library/Developer`
- 用户数据 = `analyze` 的 `/Users` 减去开发者
- 其他 = status 的已用空间减去上面四段，小于 0 时记 0

环上标明「估算」。总量、已用、可用仍用 status。分析还没完成时先显示容量，五段用占位，不填 demo 里的假数。不调用 `StorageManagement.framework`。

依赖：Q5。

**推荐：是。**

`system_profiler SPStorageDataType` 只有卷容量，没有分类。系统设置的分类来自私有框架，类别也不是这五个名字，而且和文件夹不是一一对应。目录估算会和系统设置不一致：APFS 克隆和快照会算进「其他」，没有完全磁盘访问权限的目录会偏小。

**推荐：是。**

依赖：Q23。

**推荐：是。**

这是相对当前版本的新增。当前界面只编辑 clean 白名单。

❓ **Q39** - **设置开关**

### 因 Q12 改判新开的问题

❓ **Q54** - **清理不再清空废纸篓**

同一次 `mo clean` 里有一步 `clean_trash`：把 `~/.Trash` 里已有的文件用 `rm -rf` 清掉。若缓存先移入废纸篓，紧接着又执行这一步，结果仍是永久删除。

这次重构跳过清空废纸篓。移入废纸篓的文件留在那里，由用户在 Finder 里自己清空。清理预览里不再把「清空废纸篓」算成可回收空间。

依赖：Q12。

**推荐：是。**

❓ **Q55** - **其他删除是否也进废纸篓**

Q12 只改清理。项目清理、优化里会删文件的任务，现有实现仍是 `rm -rf`。安装包在 Q31 已推荐废纸篓。卸载本来就是废纸篓。

本次只把清理改成废纸篓。项目清理和优化删除保持永久删除，页面上写明。安装包仍按 Q31 进废纸篓。

依赖：Q12。

**推荐：是。**

若否的可接受改法：项目清理和优化中的删除也改为废纸篓。大目录（如 `node_modules`）进废纸篓会很慢，也可能把废纸篓撑满。

❓ **Q56** - **不做菜单栏常驻**

demo 的「菜单栏伴侣」指一个停在屏幕顶部菜单栏里的小图标。主窗口关掉后应用仍留在后台，用户从那个图标重新打开窗口。demo 没有画出这个图标，也没有定义点开后的菜单。

这次不做菜单栏图标，也不在关闭窗口后继续留在后台。登录时启动只打开现有主窗口。

依赖：Q39。

**推荐：是。**
