# Task spec

## 背景

t043 提供后台并行扫描与 24 小时缓存后，页面仍以“预览”组织交互：必须手动点预览、预览成功后才能执行、卸载页还要单独生成预览结果。用户要求删除用户可见的预览概念：数据和执行入口直接来自后台扫描，按钮改为刷新；卸载页去掉预览步骤；破坏性确认保留。

## 契约区

### 范围

- 清理、优化、项目清理三页：去掉“预览”文案与按钮，改为“刷新”；打开页面自动显示后台结果；扫描中/无数据状态；结果完成后自动更新。
- 三页执行门禁改为“存在扫描结果即可确认”，保留确认 sheet；执行命令不变。
- clean 执行不再依赖 `clean-list.txt` 在扫描后未变化；执行前停止后台 clean 扫描。
- 卸载页删除预览步骤：选中后直接确认；删除“预览卸载”“预览结果”与相关等待态；保留“检查关联文件”作为可选详情。
- 侧栏清理角标与概览可回收量使用后台扫描结果；无数据时显示“暂无数据”。
- 三语文案与本地化 key 清理；更新受影响的测试与 spec。

### 非范围

- 后台扫描调度、并行与缓存（t043）。
- 修改 mole argv、删除落点或确认 sheet 的破坏性语义。
- 安装包页、白名单页、设置页的交互改造。
- 新增按子集执行、取消执行后的回滚。

### 验收标准

- [ ] AC-001：打开清理、优化或项目清理页时，若后台已有结果则立即显示，不需要用户先点任何按钮；无结果时显示扫描中或暂无数据。
- [ ] AC-002：三个页面的用户可见文案在三语中不再出现“预览/preview”；页头动作按钮为“刷新/Refresh”。
- [ ] AC-003：点击刷新触发对应扫描；扫描进行中不可重复触发；完成后页面自动更新并显示新的上次扫描时间。
- [ ] AC-004：存在扫描结果时执行按钮可用；点击打开确认 sheet；确认后执行原命令，取消或关闭不执行。
- [ ] AC-005：clean 执行不因扫描后 `clean-list.txt` 内容变化而被拒绝；执行开始前后台 clean 扫描已终止。
- [ ] AC-006：卸载页选择应用后直接打开确认 sheet，不再生成或展示预览结果；确认后执行卸载，取消或关闭不执行。
- [ ] AC-007：卸载确认后目标路径或 bundle id 变化时拒绝执行并提示刷新名单。
- [ ] AC-008：侧栏清理角标与概览可回收量显示后台清理结果；无结果时显示“暂无数据”，不出现“预览”。
- [ ] AC-009：扫描失败时显示刷新失败/重试文案，并保留上次成功数据。
- [ ] AC-010：安装包页、白名单页、设置页的现有确认与行为不变。
- [ ] AC-011：所有破坏性操作仍需用户在确认 sheet 中显式确认；取消、关闭或按 Esc 不执行。

### 有意不测

- 三语文案的排版长度与截断：视觉验收覆盖，不在单测中断言像素。
- 刷新过程中的扫描阶段名：t043 的后台扫描不保证提供阶段流；页面只显示扫描中。
- 卸载“检查关联文件”的 dry-run 细节：保留现有实现与测试，不在本 task 重写。

### 测试策略

- 更新 `CleanPageTests`、`OptimizeTests`、`PurgeTests`、`OptimizePurgePageTests`、`UninstallTests`、`PrewarmTests` 中依赖预览门禁的断言；旧语义测试整体替换并在 task.md 写明理由。

- 破坏性确认仍用现有 `DestructiveConfirmationView` 路径测试取消/确认。
- demo smoke 走清理、优化、项目清理、卸载四页，确认无需手动预览即可看到数据。

### 风险与回退

- 风险：去掉预览门禁后，用户可能在数据较旧时执行；卸载页直接确认可能让用户看不到关联文件。
- 回退：确认 sheet 显示扫描时间与“执行时会重新扫描”说明；保留可选“检查关联文件”。若产品不接受，可恢复独立确认摘要而不恢复预览步骤。
- 风险：旧测试大量依赖 preview 语义。
- 回退：按新语义重写测试，并在 task.md 记录被整体替换的测试及理由；不把旧预期改成实现输出。

### 依赖与约束

- 依赖 t043 的后台扫描结果与刷新 API。
- 所有用户可见文案须同步 zh-Hans、zh-Hant、en。
- 破坏性确认不可移除。
