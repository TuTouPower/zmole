# Task spec

## 背景

BackgroundScanService 在 MainActor 同步 load/save 整份 JSON，并同步读取解析 clean-list.txt。线程迁移还会引入加载覆盖新结果、旧写覆盖新写和退出丢尾批等竞态。目标是一个串行存储所有者，保证 t047 的版本顺序，同时让 I/O、编解码和解析离开 MainActor。

本文件描述本 task 完成后的目标，当前状态仍为 backlog。

## 契约区

### 范围

- 后台缓存有唯一串行存储所有者，持有已接受修订号、待写快照与水位。文件 I/O、JSON 编解码及 clean 清单读取解析均离开 MainActor；MainActor 只提交不可变快照和发布已准备好的状态。
- 服务有显式 hydration 状态。初始化加载与新扫描结果按输入版本/修订号合并；迟到加载不得覆盖已接受的新结果，不先发布“成功空缓存”造成页面闪空。
- 普通成功结果以可注入时钟进行 100 ms 尾沿合并；窗口内合并全部项、保留各自 capturedAt。持续更新时每 500 ms 至少推进一次可持久化水位，防止无限延后。
- t047 的失效版本优先串行写入，不受普通成功结果的合并延迟；显式 flush 可等待持久化水位。存储提交返回已持久化修订号，晚到旧写不得回退文件状态；缓存提交成功不是业务操作启动条件。
- 有新结果但尚未落盘时允许界面先显示，并显式区分内存版本与持久化水位；持久化成功后再确认水位。写失败保留上次完整文件和待写新快照，显示可重试的存储状态，不伪造成功。
- 提供 flush/close 生命周期；正常退出等待待写快照原子落盘，受限退出预算内完成不了则报告未完成水位。退出不能清空待写数据后声称成功；不承诺崩溃时必写普通结果，也不引入缓存与业务写入的事务耦合。
- clean 读取期间继续持有该扫描对 clean-list.txt 的文件所有权。不可变快照提取/身份校验与解析在后台完成；执行接管须等读取/解析取消退出，迟到解析不能发布旧版本。
- 维持 t047 新缓存 schema 及迁移规则，不再强制 schema=1；损坏缓存不抛解码错误到业务页，作为无缓存恢复。存储失败与无缓存状态可区分。

### 非范围

- 改变影响矩阵、共享扫描所有权、TTL、失败退避和删除语义。
- 增加多写者、每项各开独立缓存真相或把失败全部吞掉。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

- [ ] AC-001：生产缓存读写、JSON 编解码均不在 MainActor/主线程执行。
- [ ] AC-002：clean 文件读取和解析不在 MainActor；发布的是同一扫描版本的完整清单，接管期间不会读到另一个写者混入的数据。
- [ ] AC-003：虚拟时钟下两项成功相隔小于 100 ms，合并窗口结束后只发生一次普通原子写，含全部项和各自完成时间。
- [ ] AC-005：阻塞旧加载，再接受较新扫描结果并放行加载，内存与最终文件不被旧值覆盖，页面不出现成功空缓存闪回。
- [ ] AC-006：旧普通快照排队后提交较新失效版本及结果，延迟/逆序完成回调也不能把持久化水位或文件回退。
- [ ] AC-007：持续多次更新时 500 ms 内推进一次普通写水位；flush 后全部已接受普通结果落盘，正常关闭不丢尾批。
- [ ] AC-008：失效版本不受普通成功结果合并延迟；原子写失败不损坏旧文件，错误及待写状态可观察且可重试，已通过业务安全核验的操作不因缓存失败被阻断。
- [ ] AC-009：损坏或不支持 schema 的文件按无缓存恢复，服务仍能启动扫描；旧 schema 不与当前版本混读。
- [ ] AC-010：clean 解析被挡住时开始执行接管，必须先结束该读取/解析所有权；旧解析放行后不能覆盖新世代。

### 有意不测

- 不以大清单实际卡顿倍数作验收；不承诺 SIGKILL 后未 flush 的普通结果保留，缓存不是业务事务日志。

### 测试策略

- 真实缓存编解码执行器记录线程/隔离域，使用阻塞文件 I/O 证明 MainActor 可继续处理更新。
- 虚拟时钟覆盖 \<100 ms 合并、>100 ms 独立写、连续更新的 500 ms 水位和 close 尾批。
- 旧加载/新结果、旧写/新失效版本、写失败/重试、flush/关闭超时及损坏 schema 逐项交错测试。
- clean 使用临时文件和可阻塞解析器，接管后替换文件，断言旧快照不发布且全程无竞争写者。

### 风险与回退

- 风险：detached save 并发会让旧文件覆盖新文件；所有修订由唯一串行所有者接收并持久化。
- 风险：把失效版本与普通成功结果一起无限延后会加大恢复旧缓存的窗口，优先持久化失效并提供 flush 水位。
- 回退：撤回执行器与合并策略，保持 t047 的版本格式与缓存失败降级，不恢复旧写覆盖新写的并发保存。

### 依赖与约束

- 依赖 t049 的扫描服务唯一所有者，通过依赖链使用 t047 的版本、缓存格式与失败降级。
- 与 t048 共享服务/装配修改面，使用 conflicts_with；本 task 不重新实现调度。
