# Task spec

## 背景

打开卸载页会等 `uninstall --list` 把每个应用的大小算完，这段时间整页只有转圈。名单返回后，界面又对每个应用串行读取 Bundle 和 Spotlight，补版本和上次使用时间。预览和确认执行各自再跑一遍应用扫描；确认执行前还会再调用一次 `uninstall --list`。

用户已确认（2026-10-17）：冷扫描先列出已发现的应用，大小随后补上。版本和上次使用时间用这一次扫描的结果。同一次会话里，预览和确认复用这份名单。名单相对预览已变化时拒绝执行并重新扫描。

## 契约区

### 范围

- 冷扫描在全部应用大小算完之前列出已发现的应用。尚无大小的应用标为计算中，不显示为 0。大小随后补上。
- 版本和上次使用时间来自同一次扫描已经得到的数据。名单出现后，不再为每个应用查询 Spotlight 或 `NSMetadataItem`。
- 应用图标在列表可滚动之后补上。列表渲染不因逐个同步读取图标而停住。
- 同一次会话中，预览和确认执行复用当前名单，不再为了执行而重新计算每个应用的大小。
- 确认执行前核对目标身份。当前应用集合相对预览时的路径、bundle id、卸载名没有变化时，直接执行。有变化时拒绝本次执行，不 spawn 卸载命令，并重新扫描名单。
- 「检查关联文件」仍只在用户点击后，对该应用跑一次 `uninstall --dry-run`。未点击时不跑。
- 没有用户确认时不执行卸载。

### 非范围

- 不把卸载名单放进空闲预跑。那是 t031。
- 不改变关联文件 dry-run 的扫描内容和删除范围。
- 不改磁盘页、安装包页、清理、优化、项目清理。
- 不自动执行卸载。

## 上下文区

- 来源：用户 2026-10-17 批准的性能清单第 3 项。现状见 `src/zmole/Features/Uninstall/` 与捆绑 `uninstall.sh` 的 `scan_applications`。`s001` 测得 `uninstall --list` 约 36 秒，单次 `--dry-run` 约 33 秒。

### 有意不测

- 真实 `/Applications` 全量扫描耗时：不进自动测试。

### 测试策略

- 注入可分阶段返回的应用源：先给应用身份，再给大小。
- 注入会记录调用的元数据源和图标源，断言名单出现后不再逐个查询，且列表在图标完成前可滚动。
- 注入命令记录，断言预览和确认执行的参数里没有第二轮全量大小扫描；身份变化时不 spawn 卸载命令。

### 风险与回退

- 风险：跳过确认前的全量重扫后，磁盘上的应用已变化却仍被卸载。
- 回退：身份集合变化时拒绝执行并重扫。大小仍可以是上一轮的估算，执行不依赖估算字节。

### 依赖与约束

- 无前置 task。运行于 macOS。卸载仍须先预览再确认。不写 `~/.config/mole/` 的白名单。
