# 视角6 — 健壮性·可观测

## 范围与摘要

范围：docs/reviews/review_20261017_054534/\_meta/scope_files.txt 全部 152 文件（按 HEAD 94170aaa 当前磁盘状态，含未提交改动），重点 src/zmole 下 Process 执行、破坏性操作、取消语义与错误通道，另覆盖 scripts/ 与 tests/integration/。已核对 AGENTS.md、docs/blueprint/architecture.md 中「进程生命周期 / 卸载确认 / 空闲预跑 / 估算缓存」相关约束。

摘要：核心破坏性链路（确认弹窗、dry-run 前置、进程组 kill、lease 互斥、预览失效）整体扎实；主要问题集中在错误通道与可观测性——status 流错误在有历史数据后不可见（H）、overview 的 errorMessage 从不渲染（H）、失败结果被误以成功样式展示、unregister/estimation 等用户级失败被静默吞掉；另有预跑与用户预览并发写同一 clean-list.txt、磁盘测量不可取消、退出应用不清理子进程等容错缺口。全仓无任何日志设施（os.Logger/print 均无），排障只能靠瞬时 UI 文案。

## Findings

- [H][85] src/zmole/Features/Status/StatusView.swift:74 — status 流错误在首次采样成功后永远不可见 — 证据：content 分支顺序为 `.loading && snapshot == nil` → `else if let snapshot` → `else if let errorMessage`；StatusViewModel.start() 出错时只设 errorMessage（StatusViewModel.swift:133-137）不清 snapshot，故 disconnect/invalidJSON 之后页面继续显示旧值，只把指示灯变灰为 status.waiting，无错误文案无 retry 按钮。 — 修复：错误提示与 snapshot 解耦渲染（如内容顶部 banner + retry），或在 snapshot 非空时也显示 errorMessage。
- [H][80] src/zmole/Features/Overview/OverviewView.swift:14 — 概览页从不渲染 overviewViewModel.errorMessage — 证据：视图只消费 showBusyNotice、breakdown、recentOperations；OverviewViewModel.refreshHistory 失败时设置 errorMessage 并清空 recentOperations（OverviewViewModel.swift:349-351），活动卡只显示「无记录」，history 失败不可见；全文件 grep errorMessage 仅出现在 ViewModel。 — 修复：在概览内容顶部渲染 errorMessage（UtilityNotice + retry），或把失败态并入活动卡。
- [M][80] src/zmole/Features/Overview/OverviewView.swift:32 — `try? await Task.sleep` 吞掉取消，离开页面后空转并继续触发估算 — 证据：`for _ in 0..<120 where usedBytes == nil { try? await Task.sleep(...) }`；.task 被取消后 sleep 立即抛 CancellationError 被 try? 吞掉，循环仍把 120 次迭代跑完，随后在已取消上下文里执行 primeEstimate + refreshEstimateIfNeeded（再发 analyze 探测）。 — 修复：改为 do/catch 或显式 `guard !Task.isCancelled` 提前返回。
- [M][80] src/zmole/Features/Optimize/OptimizeView.swift:92 — 失败结果被同时以成功样式（checkmark）重复展示 — 证据：errorKey 非空时上方已渲染红色错误通知（87-88），紧接着 executionSummary（commandFailed 时即 stdout/stderr 摘要）又以 `symbol: "checkmark.circle"` 的 optimize.result 通知渲染；CleanView.swift:273、PurgeView.swift:94 相同。 — 修复：仅 succeeded 时渲染带 checkmark 的结果通知，失败摘要并入错误通知 detail。
- [M][80] src/zmole/Features/Settings/LoginItem.swift:34 — unregister 失败被 try? 静默吞掉 — 证据：`func unregister() throws { try? SMAppService.mainApp.unregister() }` 永不外抛；setEnabled(false) 随后读 isEnabled() 仍为 true，开关保持打开且 failureReason 为 nil，用户得不到原因。 — 修复：移除 try?，让错误走 setEnabled 的 catch 显示 failureReason。
- [M][70] src/zmole/Features/Overview/OverviewViewModel.swift:392 — 估算失败空 catch，无日志无 UI — 证据：computeEstimate 的 `catch is CancellationError {}` 与 `catch {}`（注释 Same rule）均不记录、不置 errorMessage；loadSums 抛错时 breakdown 停在 placeholder，界面只显示「—」/incomplete，无法区分无权限、未启动或超时。 — 修复：引入 os.Logger 记录失败类别，连续失败时给出可恢复提示。
- [M][65] src/zmole/Features/Overview/StorageEstimate.swift:107 — analyze 探测错误一律转 nil，信息全丢 — 证据：`catch { return nil }` 把 launchFailed/timeout/invalidJSON 折叠成「该段不可用」，与路径不存在不可区分且无日志；systemSize 同类（:161 子项读取失败 return nil）。 — 修复：区分错误类别并记录，必要时把失败原因上抛给 ViewModel。
- [M][60] src/zmole/Features/Purge/PurgePaths.swift:84 — load 失败时 errorKey 被显式清成 nil，随后保存可覆盖原文件 — 证据：catch 里 `errorKey = (error as? PurgePathsError)?.errorKey`，非 PurgePathsError（Data(contentsOf:) 的 CocoaError 等）令 errorKey 为 nil，编辑器显示空文本且无错误；PurgePathsEditorView onAppear 即 load，用户点保存即以仅含注释头的内容重写 purge_paths。 — 修复：未知错误映射通用 errorKey 并禁用保存，或保留 NSError 描述。
- [M][60] src/zmole/Features/Operations/PrewarmService.swift:203 — 预跑与用户预览并发写同一 clean-list.txt，取消为 fire-and-forget — 证据：预跑 begin() 删除并重写列表；CleanViewModel.previewClean 同刻在另一 lane 执行 begin()+dry-run（CleanViewModel.swift:105），userDidRescan 只投递异步 `Task { await process.cancel() }`（:148-151），用户侧 read(generation) 可能读到预跑进程最后写入内容；两侧对文件无互斥。 — 修复：用户预览前 await 预跑取消完成，或让预览与预跑共用同一串行化存储锁。
- [M][60] src/zmole/Features/Analyze/AnalyzeViewModel.swift:188 — 测量 worker 不可取消、扫描无取消点、会话缓存无上限 — 证据：processMeasurements 顺序 await scanner.measureSubtree；DiskScanner.walk（DiskScanner.swift:197-256）整树递归无 Task.checkCancellation 且跑在 Task.detached，离开磁盘页或刷新子树都无法停止在跑的测量；apply 把 DiskScanResult.levels 全量写入 records（:221-231），扫 /Users 这类大树时内存与 IO 无界。 — 修复：walk 周期性 checkCancellation，refreshCurrent/离页时 cancel measurementWorker 并限制缓存规模。
- [M][60] src/zmole/Features/Clean/CleanPreviewModel.swift:113 — 尺寸文本转 Int64 无溢出保护，可触发运行时 trap — 证据：parseHumanSize 对超长数字直接 `Int64((value * multiplier).rounded())`，Double 超 Int64.max 时崩溃（对比 UninstallSizeParser 用 NSDecimalNumber 与 Int64.max 比较，UninstallSnapshot.swift:305-309）；clean-list.txt 位于用户可写目录，预跑/预览会读取。 — 修复：加 `value.isFinite && value <= Double(Int64.max)` 校验，越界返回 nil。
- [M][60] src/zmole/Features/Uninstall/UninstallViewModel.swift:429 — 卸载成功/部分成功后不刷新名单也不清选择 — 证据：confirmExecution 解析结果后直接 session.finish + releaseLease，listings/selectedPaths 保持卸载前内容；已卸载 app 仍可勾选并再次 preview/execute，mole 找不到目标才报错，partial 时也无法区分哪些行已消失。 — 修复：成功或 partial 后剔除已处理 path（参照 InstallersViewModel 的 removedPaths 处理），必要时后台重扫。
- [M][55] src/zmole/App/ZmoleApp.swift:11 — 无 termination 清理，退出应用可能遗留仍在执行的 mole 子进程 — 证据：AppDelegate 只实现 applicationShouldTerminateAfterLastWindowClosed，无 applicationWillTerminate；进程组只在 cancel/超时路径 kill，应用退出后 bash+rm 等子进程继续运行，最多等到下次 stdout 写入触发 SIGPIPE 才终止。 — 修复：退出/关窗前取消并等待所有活跃 runner，补退出确认。
- [M][55] src/zmole/Features/Uninstall/UninstallView.swift:427 — errorMessageKey 分支丢弃 executionSummary，失败细节丢失 — 证据：`else if let errorMessageKey` 只渲染 title 不传 detail，而 UninstallBatchResultParser 已把 stdout/stderr 摘要放进 summary（uninstall.error.failed 时，UninstallSnapshot.swift:235-248），用户看不到 mole 失败输出。 — 修复：该分支同时传 `detail: viewModel.executionSummary`。
- [M][55] src/zmole/MoleBridge/MoleBridge.swift:296 — 全仓无日志设施，进程失败细节只存活于瞬时 UI — 证据：rg 'print(|NSLog|Logger|os.log' src/zmole 零命中；launchFailed、timedOut、退出码、stderr 仅进入当次 UI 文案，事后无法诊断，与 AGENTS.md「日志优先、用 logging」约定不符。 — 修复：在 MoleBridge 关键路径引入 os.Logger（命令、退出码、耗时、错误类别），避免记录敏感数据。
- [M][50] src/zmole/Features/Status/StatusWatchService.swift:172 — 单行 JSON 解析失败即终止整条 watch 流 — 证据：receive 中 `try? decode` 失败直接 streamEnded(.invalidJSON)，之后所有采样丢失、订阅者被 finish，只能手动 retry（注释声明 terminal 设计）；单行抖动或半行即可让状态页全面下线。 — 修复：坏行计数并跳过，连续超过阈值再终止（或降级为可恢复告警）。

- [L][60] src/zmole/Features/Clean/CleanView.swift:281 — protect 按钮对重复路径静默「成功」 — 证据：先 addPattern()（重复时置 errorMessage=「已存在」）再立即 save()；save() 开头把 errorMessage 清空并在写盘成功时 didSave=true，白名单未新增却显示已保存。 — 修复：addPattern 返回是否插入成功，失败时不调用 save 或保留错误。
