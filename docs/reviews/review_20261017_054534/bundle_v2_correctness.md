# 视角2 — 正确性

## 范围与摘要

审查范围：scope_files.txt 全部 152 文件；实现主体逐行通读 `src/zmole/App`、`src/zmole/MoleBridge`、`src/zmole/Features/*`（Clean / Uninstall / Installers / Analyze / Optimize / Purge / Status / History / Overview / Whitelist / Settings / Operations），并把 Swift 侧解析器与捆绑 mole 的**真实输出格式**逐一对照（`lib/core/base.sh` 的 `bytes_to_human`、`bin/clean.sh` 的 clean-list 写入、`lib/uninstall/batch.sh` 的 dry-run 预览行、`bin/uninstall.sh` 的 list-stream JSON、`bin/installer.sh` 的 `--list-json`、`bin/status.sh` 的 Go JSON），抽查 tests/unit 夹具与 tests/integration 脚本、scripts/ 构建脚本。越界区域（vendored mole、docs/archive、.repo_template、.claude/skills）未作为 finding 报告，仅作上下文引用。当前磁盘状态含未提交改动（MoleTheme / UtilityUI / StorageEstimateCache schema=2 / build_app_icon.sh / svg_to_png.swift / AppIconTests），均已审。

总体判断：并发骨架（MoleBridge actor + 进程组终止、OperationSession 状态机、OperationCoordinator 单租约、PrewarmService 空闲队列、StatusWatchService fan-out）设计严谨、释放路径完整，没有发现崩溃/空值解包/溢出/除零类缺陷；正确性问题集中在**解析器与实际输出格式脱节**（两处，均为确定 bug：clean 预览大小与 uninstall 关联文件清单），以及几个低可达性的状态机/时序边界。两个 H 的共性是单测夹具使用了比真实 mole 更"规整"的格式，因此全绿但线上失效。

计数：C=0，H=2，M=1，L=9，Info=2。

## 无发现声明

- 空值/解包：全仓强制解包仅 `AppLinks.swift:4`（字面量）与两处 IUO（MoleBridge.swift:111、StatusWatchService.swift:102，均在初始化闭包内同步赋值），无 `try!`/`as!`/`fatalError`；唯一 `precondition`（UninstallSnapshot.swift:97 `!apps.isEmpty`）被 `UninstallSelectionValidator` 的 noSelection 保证不可达。
- 数值/换算：无除零路径（`AnalyzeArea.share`、`OverviewStorageCard`、`freeSpaceNote` 全部先判 `total > 0`）；`st_blocks × 512`、ByteCountFormatter `.file`（十进制）与 mole 的 base-10 `bytes_to_human` 口径一致；`UninstallSizeParser` 用 Decimal + Int64.max 比较防溢出；`parseHumanSize` 的 1000/1024 单位表与 mole 十进制一致（除本报告 H#1 的格式问题外无单位错误）。
- 并发/取消：MoleBridge 每实例单 runner、generation 防串扰、`cancelAndWait` 等待终态、`onTermination` 兜底取消流；OperationSession 的 preview/confirm/execute/cancel/expire 转移与租约释放成对（cancel 路径总是 releaseLease）；PrewarmService 串行队列、去重 requeue、invalidate 清结果；StatusWatchService 单进程 fan-out、pause/stop 的 count\<=1 守卫、`streamEndInProgress` 防自等待；AnalyzeViewModel 用 generation+deduplicator 隔离新旧扫描，未发现迭代中 mutation、数据竞争或 Task 泄漏（弱引用 + MainActor 隔离完整）。
- 业务范围判定：卸载 batch 经 `UninstallSelectionValidator`（唯一名 + id 回指）、确认前 `stillMatches`（路径存在 + bundle id 未变）；installer 删除的 size/identity 复核在捆绑 CLI 侧（bin/installer.sh:923-958）而 Swift 只传会话内路径；clean/uninstall 执行前均有确认页且 `Process` 仅在确认后创建；磁盘页全程 `lstat` 只读、符号链接只计自身、跨设备目录不计入父合计、硬链接同扫描去重一次（除本报告 L#7 的显示份额边界）。
- 状态机/缓存一致性：`StorageEstimateCache` schema=2 拒绝旧格式、TTL/最大年龄判断与"不完整不落盘"逻辑自洽；`OperationCoordinator` 租约在写路径全部成对释放（含 defer 风格），held-forever 不可达；`expirePreview` 只在 ready/confirming 触发，不会与 previewing 竞争。

- 其他已核对无发现：uninstall `--list-stream` JSON 键名与 Swift CodingKeys 全对齐（path/name/bundle_id/uninstall_name/source/size/version/last_used_epoch/event）；`history --json` 的 items/size 恒有值不会误触 invalidSession；clean 阶段名目录覆盖 `start_section` 全部实际值（"Apple Silicon updates" 按设计原样显示）；demo 与 unavailable 通道的装配与回退路径正确；`PurgePathsStore.save` 的绝对路径/`~/` 校验与白名单文件格式往返无损。
