# 磁盘扫描 CPU 回归修复验证

基线：`b391e81`。验证收尾：2026-10-18T13:33:37+08:00。用户授权直接在 `main` 修复并重新打包。本报告补充原审阅在真实规模下缺失的性能验证，不改变原始采样记录。

## 根因与实现

现场旧 Release 持续约 290% CPU，三个 utility worker 分别卡在逐目录领取和子树汇总。原实现虽然把事实转存 SQLite，但每次领取都对 entries 全表扫描并排序，每次汇总又扫描整棵子树、关联检查挂载边界；目录后序也逐次排序。限制并发为 3 没有减少重复工作。

修复集中在 `DiskSessionStore.swift`：

- 新建 `scan_queue`，发现目录时入队，通过路径主键领取和删除，取消从 entries 重复寻找未访问目录。
- 后序索引配合单个游标遍历所有目录。统计按直接子项合并非链接字节，inode 索引保留独立目录合计与父范围去重贡献；直接文件优先、兄弟目录按路径排序认领，跨设备条目不参与父合并。
- 浏览队列增加 `(generation,path)` 索引，存在性检测用 `EXISTS`，避免每次状态更新计数整队列。
- SQL progress handler 在取消时中止查询；阶段事务保留失败回滚与空间配额语义。
- 记录 SQLite VM 指令数，回归测试直接约束生产对象工作量，不靠易受机器负载影响的秒数断言。

## 优化构建对照

使用相同 Swift 编译参数 `swiftc -O`，编译基线与修复版生产 `DiskSessionStore` / `LiveDiskScanner`；基线仅增加同样的 VM 指令计数。夹具固定，三轮交错执行 baseline/fixed 与 fixed/baseline。以下为中位数，CPU 为进程 CPU 时间：

|1,024 目录|基线耗时|修复耗时|基线 CPU|修复 CPU|基线 SQL 指令|修复 SQL 指令|
|---|---:|---:|---:|---:|---:|---:|
|队列消费|1.092 s|1.500 s|0.963 s|1.145 s|14,336,994|256,473|
|汇总 / 4,096 文件|8.166 s|0.116 s|4.994 s|0.114 s|156,050,649|676,606|

汇总阶段 CPU 时间下降约 97.7%，SQL 指令减少约 99.6%。队列增加独立取出删除操作，小规模耗时略增；其指令增长已从重复全扫改为有索引的领取。没有把该阶段的耗时写成改善。

扩展到 10,240 目录 / 40,960 文件，修复版汇总耗时 1.338 s、CPU 1.320 s、6,760,454 条 SQL 指令，结果合计 40,960，与输入一致；目录数扩大十倍，指令约增十倍。
